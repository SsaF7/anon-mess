# anon-mess
Анонимный месседжер на Python

P2P: отдельного сервера нет, каждый участник запускает один и тот же файл.

## Запуск

```
pip install -r requirements.txt
python3 mess_peer.py
```

1. Введите имя и порт, на котором ваш узел будет принимать подключения.
2. Введите `ip:port` любого участника, который уже в сети.
   Если вы первый — оставьте пустым.

Узлы обмениваются списками участников и сами подключаются друг к другу,
поэтому достаточно знать адрес одного из них. Сообщения пересылаются
по сети дальше, так что доходят даже до тех, с кем нет прямого соединения.

Команды: `/peers` — список подключённых участников с отпечатками, `/quit` — выход.

## Шифрование

Сообщения шифруются сквозным шифрованием: прочитать их могут только участники,
а узлы, через которые сообщение идёт по пути, — нет.

- При каждом запуске создаётся новая пара ключей: Ed25519 (подпись) и X25519
  (шифрование). На диск ничего не сохраняется.
- Отпечаток участника — хэш его публичных ключей, он же его id в сети.
  Свой отпечаток показывается при запуске, чужие — в `/peers` и рядом с
  каждым сообщением.
- Текст, имя и время шифруются случайным ключом ChaCha20-Poly1305, а этот
  ключ — отдельно для каждого получателя через одноразовый ключ X25519.
- Каждое сообщение подписано отправителем: подделанные или изменённые в пути
  сообщения отбрасываются, выдать себя за другого участника нельзя.

Чтобы быть уверенным, что вы переписываетесь именно с тем, с кем думаете,
сверьте отпечатки по другому каналу (лично, по телефону).

## Ограничения

- Чтобы к вам могли подключиться из интернета, порт должен быть открыт
  (проброс порта на роутере). В локальной сети работает сразу.
- Сообщение получают только те, о ком отправитель знал в момент отправки.
  Новые участники старую переписку не видят.
- Нет ротации ключей, как в Signal: если приватный ключ участника утечёт
  во время сеанса, можно расшифровать сообщения этого сеанса, адресованные ему.
- Узлы сети видят IP-адреса, отпечатки и кто когда отправил сообщение
  (но не текст и не имена).
- Подключиться и читать переписку может любой, кто знает адрес узла.
